# MadPisaBot Enhanced

Telegram-бот на aiogram 3 и SQLAlchemy 2. Python 3.12+; SQLite.
Все игровые сроки хранятся как Unix timestamps UTC. В сообщениях даты и время
отображаются в **МСК (UTC+3)** независимо от часового пояса сервера.

## Запуск

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# Указать BOT_TOKEN в .env
.venv/bin/python main.py
```

`DATABASE_URL` по умолчанию — `sqlite+aiosqlite:///database.db`; относительный путь
отсчитывается от рабочей директории запуска. Для другого расположения можно указать
абсолютный путь, например `sqlite+aiosqlite:////srv/bot/database.db`.
ID владельцев бота задаются в `config.py`.
Запускайте один экземпляр polling для одного токена и БД.

## Миграции и восстановление

Миграции Alembic выполняются автоматически перед polling. Запустить их отдельно,
без подключения к Telegram:

```sh
.venv/bin/python -m bot.db.migrate
```

Перед изменением существующей БД создаётся согласованная SQLite-копия
`database.db.backup-<дата UTC>` рядом с ней; путь выводится в журнал.
Повторный запуск актуальной миграции ничего не меняет.
Миграция старой схемы сохраняет размеры, ID, кеш имён и блокировки.
Существующий `next_dick` уже является UTC Unix timestamp: сдвиг на три часа
не выполняется; `NULL` превращается в `0`.
При дубликатах ключей или неизвестной структуре миграция останавливается,
а транзакция откатывается. Перед исправлением данных сохраните резервную копию;
бот не выбирает автоматически, какой из конфликтующих профилей удалить.

Для восстановления остановите бот и другие подключения к БД, сохраните текущий
файл и возможные файлы `-wal`/`-shm` отдельно, затем замените БД выбранной резервной
копией. Не оставляйте рядом WAL/SHM от заменённой БД. Для полного отката к прежнему
состоянию используйте соответствующую прежнюю версию кода. Старый JSON `/export`
по-прежнему содержит только игровые размеры и задержки; для резервирования семей
используйте полную копию SQLite.

## Игра и поддержка отстающих

- `/dick` — отдельный результат −5…10 см раз в 12 часов в каждом чате.
- `/info` — свой профиль или профиль автора сообщения, на которое дан ответ.
- `/top`, `/top_dick` — топ 15 игроков.

Для положительного броска `r`, размера лидера `L` и исходного размера игрока `x`:

```text
M = max(1, (L − 42) / 420)
бонус = min(round_half_up(r × (M − 1)), max(0, L − 42 − (x + r)))
итог = x + r + бонус
```

Для нулевого или отрицательного броска бонус равен нулю. Множитель пересчитывается
по лидеру до каждого броска и действует неограниченно. Округление математическое
(`.5` вверх), расчёт производится целочисленно. Базовый результат не обрезается;
только бонус ограничивается отставанием в 42 см. Например, при лидере 777 см,
размере игрока 730 см и броске +4 расчётный бонус +3 обрезается до +1: итог 735 см.
При исходных 727 см и броске +10 бонус равен нулю: базовый бросок уже оставил 40 см.

Расчётные 42 попытки соответствуют примерно трём неделям при неизменном лидере и
постоянном +10. Из-за округления иногда нужна 43-я попытка. При `M = 1` бонуса нет.
Платный сброс задержки не изменяет формулу.

## Семьи

Действия изолированы по чатам и доступны в группах, супергруппах и каналах.
Игровая личность — отправитель `sender_chat`, если сообщение отправлено от имени
канала/анонимной группы, иначе личный аккаунт.

| Команда | Действие |
| --- | --- |
| `/marry [id]` | Предложить брак по ID или в ответ на сообщение игрока |
| `/accept [id]` | Принять предложение по номеру или ответом на предложение бота без аргумента |
| `/decline [id]` | Аналогично отклонить предложение |
| `/divorce` | Развестись после собственного подтверждения |
| `/couples [duration\|children] [page]` | Пары по длительности брака или числу детей, по убыванию, 10 на страницу |
| `/sex` | Предложить супругу секс |
| `/namechild <id> <имя>` | Назвать или переименовать ребёнка; 1–64 символа |
| `/orphanage <id>` | Предложить безвозвратно удалить ребёнка |

Брак, секс и добровольная сдача ребёнка требуют согласия второго супруга.
Развод подтверждает только инициатор. Предложения сохраняются в БД, действуют 15 минут
и принимаются только адресатом в исходном чате. Для личных аккаунтов доступны
кнопки; канал/анонимный администратор отвечает командой от той же игровой личности.
Подтверждение кнопкой личного аккаунта не подтверждает действие за канал.
При переносе группы в супергруппу семьи и статистика переносятся, а незавершённые
предложения отменяются: идентификаторы старых сообщений могут измениться.
Telegram должен разрешать соответствующей личности отправлять сообщения
в месте подтверждения; бот не обходит ограничения на публикацию в каналах.

Секс доступен раз в час на пару после подтверждения. Вероятность беременности
равна 25%; вынашивает супруг с меньшим текущим размером, при равенстве выбирается
случайно. Если выбранный супруг уже беременен либо у него не прошли 48 часов после
родов, новая беременность не начинается, другой супруг вместо него не выбирается.
Ограничения персональные внутри чата: оба супруга могут быть беременными одновременно,
если размеры поменялись. Послеродовая пауза сохраняется после смены супруга.

Беременность длится 9 суток. Фоновая обработка происходит раз в минуту и при запуске;
перед игровыми действиями учитываются уже наступившие роды. Дата рождения —
запланированный срок, а не момент перезапуска. Уведомления о рождении повторяются
после временных ошибок доставки; крайне редкий сбой между отправкой Telegram
и записью результата может повторить уведомление, но не само рождение.

Количество детей не ограничено. Ребёнок рождается с размером 0 и может сразу играть.
Каждый готовый ребёнок получает независимый бросок −5…10 при `/dick` любого родителя,
даже если сам родитель пока на задержке. Детская задержка 12 часов общая для обоих
родителей. Дети не получают бонус поддержки и не входят в `/top`; имя, возраст,
размер и задержка видны в `/info` обоих супругов. Длинные ответы разбиваются на сообщения.

**Добровольная сдача через `/orphanage` удаляет ребёнка навсегда.**
При разводе дети сохраняются в детдоме с именами и статистикой, временно не играют
и не учитываются в списке пар. Они возвращаются при повторном браке тех же двух
игровых личностей **в том же чате**, включая прежние задержки. Продолжительность
нового брака начинается заново; часовой срок секса той же пары не сбрасывается.
Незавершённые беременности при разводе отменяются. Если срок родов уже наступил,
сначала фиксируется рождение, и ребёнок сохраняется в детдоме.
Усыновление не предусмотрено.

## Существующие служебные команды

Сохранены `/giveuserlink`, `/export` (владелец группы), `/buy` и `/pay`,
`/feedback`, а также команды владельца бота `/editsize`, `/refund`,
`/sendalert`, `/banfeedback`, `/unbanfeedback`, `/sendto`.
Оплаченный сброс снимает только личный `/dick` выбранного игрока во всех чатах;
задержки детей, секса и беременности сохраняются.
